# HabitForge — фронтенд

Трекер привычек: создание привычек с гибкой периодичностью, отметки выполнения, стрики, дашборд дня, категории, авторизация. Pet-проект, сделанный как полноценное fullstack-приложение, а не как упражнение по туториалу.

**Живая версия:** [habit-forge-alpha.vercel.app](https://habit-forge-alpha.vercel.app/)
**Бэкенд:** [Roman-oryol/habit-forge-api](https://github.com/Roman-oryol/habit-forge-api)

> API хостится на бесплатном тарифе Render и «засыпает» при простое. Первый запрос после паузы может занять около минуты (холодный старт) — дальше всё работает быстро.

## Возможности

- Регистрация, вход, выход; защищённые роуты, редиректы
- Сессия на 30 дней: access-токен обновляется тихо, пароль повторно вводить не нужно
- Восстановление пароля по ссылке из email
- Тосты об успехе и ошибках операций (shadcn Toast на Base UI)
- CRUD привычек (форма на React Hook Form + Zod)
- Три вида периодичности: каждый день, конкретные дни недели, N раз в неделю
- Отметка выполнения за день
- Стрики: отдельный алгоритм для каждого вида периодичности
- Дашборд дня: выполнено сегодня, текущий стрик, консистентность за неделю
- Категории: полный CRUD, фильтр привычек по категории
- Светлая и тёмная тема (без мерцания при загрузке)
- Адаптивная вёрстка, app-shell layout

## Стек

- **React 19 + TypeScript + Vite**
- **React Router** — роутинг, guard-компоненты для приватных и публичных страниц
- **TanStack Query** — серверное состояние, кеш, инвалидация после мутаций
- **React Hook Form + Zod** — формы и валидация, в том числе кросс-полевая
- **Tailwind CSS v4 + shadcn/ui** (стиль `base-nova`, основан на Base UI, не на Radix)
- **Vitest** — тесты бизнес-логики (24 теста, 3 файла)

## Технические решения

**Единая точка входа в HTTP.** Все запросы идут через `apiFetch<T>` в `api/client.ts`: он подставляет `Authorization`, парсит JSON, обрабатывает `204`, бросает типизированный `ApiError`. При ответе `401` на запрос с токеном токен очищается — приложение само возвращается на логин.

**Тихое обновление сессии.** Access-токен живёт 15 минут, refresh-токен 30 дней. На `401` `apiFetch` меняет refresh-токен на новую пару и повторяет запрос один раз. Обмен идёт под Web Locks: refresh-токен одноразовый, и параллельные запросы (или вкладки) делают ровно один обмен, остальные берут уже готовый результат. Если сервер недоступен (сеть, 5xx, например холодный старт Render), пользователя не разлогинивает: выход происходит только когда сервер отклонил refresh-токен. Поведение покрыто тестами в `api/client.test.ts`.

**Токен как внешнее хранилище.** `lib/auth-token.ts` — обёртка над `localStorage` с подпиской (включая событие `storage` для синхронизации между вкладками). React читает его через `useSyncExternalStore`, поэтому логин/логаут в одной вкладке отражается в остальных. Та же схема у темы.

**Очистка кеша при выходе.** При пропаже токена вызывается `queryClient.clear()`, чтобы данные предыдущего пользователя не были видны следующему.

**Разные Zod-схемы для формы и домена.** Форме удобна плоская структура (`frequencyType` + опциональные `days` / `timesPerWeek`), домену — вложенный discriminated union `Frequency`. Между ними явные мапперы, а не одна модель, натянутая на обе задачи.

**Три алгоритма стриков.** Дневная, по дням недели и «N раз в неделю» — принципиально разная логика. Каждый алгоритм — отдельная чистая функция, диспетчер выбирает нужную через `switch` по union с исчерпывающей проверкой типов.

**Тесты на уровнях ответственности.** `isHabitDueToday` покрыта отдельно; функции, которые её используют, тестируют только свою агрегацию — упавший тест сразу показывает слой с проблемой.

**Авторизация: компромисс.** Access- и refresh-токены хранятся в `localStorage`, access уходит как `Bearer`. Фронтенд и API на разных доменах, поэтому httpOnly-cookie потребовали бы настройки `SameSite`/CORS-credentials и защиты от CSRF. Цена выбора — уязвимость к краже токена через XSS. При общем домене предпочёл бы httpOnly-cookie.

## Локальный запуск

Нужен запущенный бэкенд (см. README [habit-forge-api](https://github.com/Roman-oryol/habit-forge-api)).

```bash
npm install
cp .env.example .env    # или создайте .env вручную
npm run dev             # http://localhost:5173
```

`.env`:

```
VITE_API_URL=http://localhost:3000/api/v1
```

Скрипты:

```bash
npm run dev       # dev-сервер
npm run build     # type-check + продакшн-сборка
npm run test      # Vitest (watch)
npm run lint
```

## Деплой

Vercel, автодеплой из `main`. В настройках проекта задаётся `VITE_API_URL` (URL продакшн-API с `/api/v1`). Для SPA-роутинга нужен `vercel.json` с rewrite на `index.html`. На стороне API в `FRONTEND_URL` должен быть указан адрес фронтенда (CORS).
